# Project Architecture — AEROBLADE Reproduction (SPL3 Module 1)

A from-scratch implementation and reproduction study of **AEROBLADE: Training-Free
Detection of Latent Diffusion Images Using Autoencoder Reconstruction Error**
(the paper PDF sits in the project root).

The system answers one question — *was this image produced by a latent diffusion
model?* — without training any classifier. It exploits a structural property of LDMs:
an image generated by an LDM was decoded from that model's own latent space, so
pushing it back through that model's autoencoder reproduces it almost exactly. A real
photograph has no such privileged representation and reconstructs measurably worse.

---

## 1. Core method

For an input image `x`:

1. Resize to 512×512, scale to `[-1, 1]`.
2. Run `x` through **each** candidate LDM autoencoder (encode → decode) to get `x̃_AE`.
3. Measure perceptual distance `d(x, x̃_AE)` using **LPIPS layer 2** (VGG backbone).
4. Take the minimum over autoencoders:

   ```
   Δ_Min(x) = min_AE  LPIPS₂(x, AE(x))          # paper Eq. 2
   score(x) = −Δ_Min(x)                          # higher ⇒ more likely generated
   verdict  = "AI-generated" if Δ_Min(x) < threshold else "Real"
   ```

5. The AE achieving the minimum is reported as the **attributed generator family**.
6. The un-averaged LPIPS₂ error map localizes *which regions* drove the decision — blended
   onto the input and averaged per superpixel region (§6).

### Autoencoder bank (`src/config.py: AE_CONFIGS`)

| Key | Source repo | Component | Type |
|---|---|---|---|
| `sd1` | `stable-diffusion-v1-5/stable-diffusion-v1-5` | `vae` | KL-regularized (`AutoencoderKL`) |
| `sd2` | `sd2-community/stable-diffusion-2-1` | `vae` | KL-regularized (`AutoencoderKL`) |
| `kandinsky` | `kandinsky-community/kandinsky-2-1` | `movq` | Vector-quantized (`VQModel`) |

The two AE families have incompatible APIs, so `reconstruct()` branches on type:
KL sampling goes through `latent_dist` + `scaling_factor`; VQ returns latents directly.

### Two subtle constants that were bug sources

- **`LPIPS_LAYER_INDEX = 1`** — the `lpips` package's `retPerLayer` list is 0-based, so
  the paper's *LPIPS₂* is index **1**. Using index 2 computes LPIPS₃ and measurably
  degrades separability (this happened in an early Kaggle run). The display name
  (`LPIPS_LAYER_NAME = 2`) is kept as a **separate** constant so labels and indexing
  can never be confused again.
- **`HF_HOME` is set in `config.py` at import time** (`D:\HF_Models`) — `huggingface_hub`
  resolves its cache path on import, so `config` must be imported before `diffusers`
  anywhere in the process or the override is silently ignored.

## 2. Module map

```
src/
  config.py            single source of truth: AE bank, LPIPS layer, paths, HF_HOME
  autoencoders.py      loads the 3 AEs from HF (per-AE failure is non-fatal)
  reconstruct.py       image → tensor → encode/decode → tensor → PIL
  distance.py          LPIPS₂ scalar error + spatial heatmap (model loaded once)
  detect.py            CLI: single/multi-image detection, JSON report + figure
  download_real.py     builds the real-image calibration corpus from LAION parquet
  compute_threshold.py threshold via F1-maximization over precomputed CSVs
  calibrate_target_fpr.py  threshold via target-FPR percentile (the deployed one)
  calibrate.py         end-to-end local calibration (score + threshold, CPU, slow)
  evaluate.py          reproduces the paper's per-generator AP / TPR@5%FPR tables

kaggle/
  score_dual_gpu.py            scores real + generated in one dual-T4 run
  score_real_dual_gpu.py       real/ only
  score_generated_dual_gpu.py  generated/ only
  KAGGLE_INSTRUCTIONS.md       notebook setup + sanity checks
```

### Dependency direction

```
config.py  ──┬──> autoencoders.py ──┐
             ├──> reconstruct.py  ──┼──> detect.py      (inference)
             ├──> distance.py     ──┘   calibrate.py    (local calibration)
             │
             └──> compute_threshold.py / calibrate_target_fpr.py / evaluate.py
                        (CSV-only: no torch, no model loading)
```

The lower-right group deliberately touches **no GPU code** — it consumes score CSVs
only, which is what makes the split-compute workflow (§4) possible.

Generator folders present: SD1.1, SD1.5, SD2.1, Kandinsky 2.1, Midjourney v4 / v5 / v5.1.

### `download_real.py` — real-corpus construction

Reproduces the paper's Sec. 7.1 recipe exactly, because the threshold's quality depends
entirely on how representative the real set is:

- Filter LAION parquet rows: `min(W,H) ≥ 512`, `W·H ≤ 768²`, aesthetic score ≥ 6.5,
  plus `punsafe`/`pwatermark` caps.
- **Center-crop** to 512×512 — never resize, since interpolation blur suppresses the fine
  detail that makes real images hard to reconstruct.
- Save as **PNG**, matching `data/generated/`, avoiding a JPEG-vs-PNG compression bias
  between the two classes.
- Concurrent (32 threads) and **resumable**: successes inferred from files on disk,
  dead URLs recorded in `_download_manifest.csv` and skipped on rerun. Rows are keyed by
  the LAION `hash` column, not positional index, so multiple parquet shards can be mixed.

## 4. Compute topology (why the pipeline is split)

A single image costs three AE round-trips plus LPIPS ≈ **40 s on CPU**. At 8,024 images
that is ~3.7 days locally — impractical. So scoring and threshold-fitting are separated:

```
  ┌─ Kaggle (2× T4 GPU) ─────────────┐        ┌─ Local (CPU) ────────────────────┐
  │ kaggle/score_dual_gpu.py         │        │ src/evaluate.py                  │
  │   → real_scores.csv              │ ──CSV─>│ src/calibrate_target_fpr.py      │
  │   → gen_scores.csv               │        │   → models/threshold.json        │
  │   ~1.5–2.5 h wall clock          │        │ src/detect.py (single images)    │
  └──────────────────────────────────┘        └──────────────────────────────────┘
```

Notable design choices in the Kaggle scripts:

- The parent process **writes its worker to a real `.py` file and launches it twice via
  `subprocess`**, one per GPU — not `multiprocessing.Process`. CUDA requires the `spawn`
  start method, which cannot pickle a function defined in a notebook cell
  (`AttributeError: Can't get attribute '_worker'`). Separate interpreter invocations
  communicate through files only, so the script survives being pasted into a cell.
- `score_dual_gpu.py` partitions by **whole directory**: GPU 0 takes all of `real/` plus
  the model folders in `GPU0_GENERATED_MODELS`; GPU 1 takes the rest. Nothing is split
  mid-directory. The single-purpose variants (`score_real_*`, `score_generated_*`) instead
  interleave `[part::num_parts]` for even load.
- Workers use `spatial=False` LPIPS (scalar only — no heatmap needed for bulk scoring);
  local `distance.py` uses `spatial=True` so one model serves both the scalar and the map.

## 5. Calibration — two competing strategies

Both write the same `models/threshold.json` that `detect.py` reads.

| Script | Rule | Problem it solves / creates |
|---|---|---|
| `compute_threshold.py` | maximize F1 over pooled real+generated | With 7,000 generated vs 1,024 real, misclassified real images barely dent precision — implicitly tolerates a high real-image FPR |
| `calibrate_target_fpr.py` | threshold = `target_fpr`-th percentile of real scores | Directly bounds false accusations of real photos; mirrors the paper's own TPR@5%FPR metric. **This is the deployed one.** |

`calibrate.py` is the self-contained local version: it scores `data/real/` and
`data/generated/` itself and then applies the F1 rule — usable for small sets, far too
slow for the full corpus.

**Currently deployed threshold** (`models/threshold.json`):

```
threshold      = 0.01681   (Δ_Min, LPIPS₂)
method         = target_fpr_0.05
AP             = 0.9894
achieved FPR   = 5.08 %  on 1,024 real images
TPR            = 75.9 %  on 7,000 generated images
```

## 6. Inference path (`src/detect.py`)

```
python src/detect.py <image> [<image> ...]
```

Per image it produces:

- `results/<stem>_report.json` — per-AE distances, `delta_min`, `attributed_ae`, score,
  threshold + whether it was calibrated, verdict, source size, low-res flag, and the
  top-10 `region_attribution` entries.
- `results/<stem>_analysis.png` — 3-panel figure: input | reconstruction (winning AE) |
  **error overlay**, titled with the verdict and Δ_Min vs threshold.

### Error localization (the overlay panel)

A standalone heatmap panel forces the reader to mentally align two images and reduces the
result to "the yellow parts are worse" — useless to quote in a write-up. The third panel
therefore does two things at once:

- **Alpha-blended wash.** `overlay = input·(1−α) + cmap(error)·α` (α = 0.55), so error
  intensity is read at the exact pixel it belongs to, in one glance. The wash saturates at
  the **99th percentile** of the error map rather than its max — the distribution is
  long-tailed and a couple of extreme pixels would otherwise crush everything else into the
  dark end of the colormap. The colorbar is marked `extend="max"` so that clipping is
  visible rather than implied.
- **Superpixel region attribution.** `region_attribution()` runs SLIC (~160 segments,
  compactness 10) over the input, so regions follow colour/texture boundaries and land on
  coherent things instead of an arbitrary grid, then averages the LPIPS error inside each
  via `np.bincount`. The 6 highest-error regions are outlined and annotated **in place**
  with their mean error; the top 10 go into the JSON with mean error, area fraction, and
  centroid. That turns a visual impression into a sentence you can actually write —
  *"error concentrates on the chain-link fence and grass (0.071, 0.064) while the flat
  banner behind stays near 0.02"* — which is also the paper's Sec. 5.4 complexity finding
  showing up at the level of a single image.

Two details that keep the panel readable: labels are filtered to be ≥70 px apart
(`_spread_out()`), because the top-error regions are usually neighbours in one hot area and
labelling them blindly stacks unreadable text in one corner; and label text carries a dark
`path_effects` stroke so it stays legible over both ends of the wash without a background
box that would hide the image.

Two guardrails beyond the paper:

- **Uncalibrated-threshold warning.** Falls back to `DEFAULT_THRESHOLD = 0.01` and warns
  loudly if `models/threshold.json` is absent, and records `threshold_calibrated: false`
  in the report so a provisional verdict can't be mistaken for a calibrated one.
- **Low-resolution warning.** The paper only ever evaluates images with short side ≥ 512.
  Below that, the resize becomes an *upscale* whose interpolation blur suppresses fine
  detail and biases Δ_Min **downward — i.e. toward a false "AI-generated" verdict**. The
  detector flags this in the console, the JSON, and on the figure rather than silently
  returning a biased answer.

## 7. Evaluation (`src/evaluate.py`)

Reports both framings, deliberately:

- **Per-generator** — 1,024 real vs one model's 1,000 images at a time, printed side by
  side with the paper's published Tab. 1 (AP) and Tab. 3 (TPR@5%FPR) values, which are
  hard-coded in `PAPER_REFERENCE`. This is the only apples-to-apples comparison, since the
  paper never reports a pooled number.
- **Pooled** — real vs all 7,000 generated under one global threshold. Strictly harder
  (one cut must work for the worst-separating generator) but it's what the deployed
  detector actually faces.

Folder names are matched to paper rows by **longest-substring** so `midjourney-v5-1`
isn't captured by the `midjourney-v5` key.

### Current reproduction status

| Generator | Our AP | Paper AP | Our TPR@5% | Paper TPR@5% |
|---|---|---|---|---|
| SD1.1 | 0.948 | 0.979 | 0.972 | 0.981 |
| SD1.5 | 0.949 | 0.978 | 0.946 | 0.963 |
| SD2.1 | 0.975 | 0.994 | 0.992 | 0.995 |
| KD2.1 | 0.977 | 0.999 | 0.982 | 0.999 |
| **MJ4** | **0.892** | 0.999 | **0.484** | 0.997 |
| **MJ5** | **0.883** | 0.997 | **0.496** | 0.993 |
| **MJ5.1** | **0.862** | 0.996 | **0.440** | 0.989 |

Two distinct discrepancies, analyzed in depth in `MIDJOURNEY_DEGRADATION_ANALYSIS.md`:

1. **Uniform ~0.02–0.03 AP gap on every generator** — most likely the independently-drawn
   real calibration set (1,024 images from a different LAION sample than the paper's fixed
   1,000). AP is threshold-independent, so this isn't a calibration artifact; and the
   paper's own Sec. 5.4 finding (reconstruction error tracks image complexity) means
   *which* real images you draw shifts the whole real-score distribution.
2. **MJ-specific collapse (TPR roughly halved)** — Midjourney detectability rides entirely
   on a fragile cross-model property: 99.7–99.9 % of MJ images get their minimum from the
   **SD2** AE (paper Tab. 2), even though MJ isn't an SD model. Leading suspects, in the
   order the doc recommends testing them:
   - `.sample()` vs `.mode()` — `reconstruct()` draws a *random* sample from the KL
     posterior, injecting run-to-run noise. Harmless for confident matching-AE cases,
     amplified for MJ's marginal cross-AE case. **Testable, highest value.**
   - Real-set difference shifting the 5 %-FPR cut (0.0168) — MJ's mean score
     (0.0173–0.0192) sits almost exactly on it, so a small threshold move sweeps a large
     share of MJ's mass across the line. Explains "AP down moderately, TPR collapsed".
   - **SD2 VAE provenance** — `stabilityai/stable-diffusion-2-1` has been *removed* from
     Hugging Face entirely, so the project uses the third-party `sd2-community` mirror.
     Untestable now that the reference artifact is gone; documented as an open,
     deprioritized suspect rather than a chaseable lead.

## 8. Typical workflows

**Detect a single image**
```
venv312\Scripts\python src/detect.py test/1.png
```

**Full reproduction from scratch**
```
python src/download_real.py --target 1000        # build real corpus
# upload data/ to Kaggle, paste kaggle/score_dual_gpu.py, run  → 2 CSVs
# drop real_scores.csv + gen_scores.csv in project root
python src/evaluate.py                            # paper comparison tables
python src/calibrate_target_fpr.py --target-fpr 0.05   # → models/threshold.json
```

**Small-scale local calibration (no Kaggle)**
```
python src/calibrate.py      # scores data/ on CPU, F1 threshold — slow
```
